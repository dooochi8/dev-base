# Write A PRD

ユーザーへの聞き取りとコードベース探索を通じて、実装に耐える PRD を作る。

## 進め方

1. まず、解きたい問題と考えている解決案をユーザーに説明してもらう。
2. コードベースを探索し、現状の実装、既存機能、制約を確認する。
3. 不明点や設計分岐を一問ずつ詰める。必要なら `grill-me` と同じ姿勢で進める。
4. 実装で触るべき主要モジュールや責務のまとまりを整理する。
5. テスト対象にすべき重要な振る舞いを整理する。
6. 合意できた内容を PRD にまとめる。

## 原則

- ユーザー視点の問題設定から始める。
- コード上の事実で補強できることは補強する。
- 実装詳細に入りすぎず、判断と振る舞いを中心に書く。
- 後から見ても判断理由が分かる形にする。
- ファイルパスやコード片は、すぐ古くなるので原則書かない。

## PRD テンプレート

```md
## 問題

ユーザーが今どんな問題を抱えているか。

## 解決方針

その問題をどう解くか。ユーザーに見える振る舞いを中心に書く。

## ユーザーストーリー

1. As a <actor>, I want <feature>, so that <benefit>

数は惜しまず、この機能で実現したい振る舞いを広く洗い出す。

## 実装上の判断

- 主要なモジュールや責務
- インターフェース上の判断
- API やスキーマ上の判断
- 技術的な制約や補足

## テスト方針

- 何をもって良いテストとするか
- どの振る舞いを重点的にテストするか
- 既存コードベースで参考にするテストがあるか

## スコープ外

今回の PRD で扱わないこと。

## 補足

その他、実装前に残しておきたい前提や注意点。
```

## 完了条件

- 問題と目標の振る舞いが明確
- ユーザーストーリーが十分に洗い出されている
- 実装上の主要判断が記録されている
- スコープ外が明示されている
