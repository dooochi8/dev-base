# PRの検証成果物

PR本文の「検証」に貼る証拠の形。人間のレビュアーが、コードを読む前に振る舞いを確かめられるようにする。`verify` の報告フォーマットを、PR向けに機能マップのIDと証拠のリンクで補ったもの。

## 決定論的な検査

| コマンド | 結果 |
|---|---|
| `node scripts/harness-check.mjs` | `harness: N rules passed.` |
| `<型チェック>` | |
| `<lint>` | |
| `<テスト>` | `<合格数 / 総数>` |

## 振る舞いの証拠

| 機能ID・入口 | 操作 | 期待 | 結果 | 証拠 |
|---|---|---|---|---|
| `<feature-id>` / `<入口>` | `<実行したコマンドか操作>` | `<観測できる結果>` | ✅ / ❌ | `<スクリーンショット・動画・ログ・ARIAスナップショットへのリンク>` |

- UIの変更は、変更前と変更後のスクリーンショット、または操作の動画を付ける。
- 状態遷移を変えたら、`docs/statecharts/` の図の差分と、変えた遷移を通る証拠を付ける。
- プロパティベーステストは、性質の名前、生成した入力の数、シードを書く。
- 失敗した検証は、出力の要点を引用して原因を書く。加工・省略しない。

## 検証できなかったこと

| 項目 | 理由 | 残る確認 |
|---|---|---|
| | | |

なければ「なし」と書く。実行していない検証を確認済みと書かない。
