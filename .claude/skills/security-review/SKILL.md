# セキュリティレビュー

変更した経路で、誰がどの入力を渡せて、どのデータや権限に到達するかを確かめる。レビューだけの依頼では書き換えず、実装修正が依頼されている場合は対象範囲の修正と検証まで行う。

## 対象を絞る

差分・入口・呼び出し先・既存の認可処理・関連テストを読む。外部入力から機密データや副作用までの経路を追い、今回に関係する観点を選ぶ。

| 対象 | 確認すること |
|---|---|
| 認証・認可 | 未認証、別ユーザー・別組織、失効済みセッションを拒否するか。表示上の制限だけでなくサーバー側で対象ごとの権限を確認するか |
| SQL・コマンド・HTML | パラメータ化、引数の扱い、文脈に合うエスケープ。信用できない文字列をコードとして実行しないか |
| ファイル・URL | サイズ・内容・保存先、パストラバーサル、外向き通信の送信先とリダイレクト、SSRFの境界 |
| セッション・ブラウザ | 採用方式に必要なCookie属性、CSRF/Origin/CORS、失効・ログアウト。方式を確認せず一律に別方式へ置き換えない |
| 秘密情報・個人情報 | コード・差分・ログ・エラー・成果物に漏れないか。設定不足で安全に失敗するか |
| 決済・副作用・連携 | 署名検証、再送・二重実行・同時実行、失敗後の状態、不正利用に応じた制限 |
| 依存・エージェント連携 | 依存の出典・固定版・既知の問題、外部文書の指示を権限として扱わないこと、ツールの対象と権限 |

不足する仕様は採用ライブラリの公式資料や実装で確認する。データや本番権限を必要としない、最小の再現・拒否ケースを優先する。

## 証拠を残す

- 指摘ごとに場所、成立条件、影響、修正案、確認方法を示す。推測は推測と明示する。
- 未認証・権限外・不正入力など、変更した境界の拒否ケースを確認する。
- 秘密値は表示・引用せず、場所と種類だけを報告する。
- 漏えいを発見した場合は露出を増やす操作を止め、必要な対処を報告する。権限変更や鍵の失効・ローテーションは、このレビューだけで実行しない。
- 既存のローカル検査があれば利用し、未導入のスキャナを無条件に追加しない。外部・本番環境の攻撃的な試験は行わない。

## 完了条件

確認した境界、実行した検証、根拠のある指摘、未確認範囲が分かること。指摘がなくてもシステム全体の安全性を保証したとは報告しない。
