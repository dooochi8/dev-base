# PRD Lite

作業がやや大きく、実装前に短い整理メモが欲しいが、本格的な PRD までは不要なときに使う。

## テンプレート

```md
## 問題

今なにが壊れているか、足りないか、または高コストか。

## 目標の振る舞い

変更後、ユーザーや呼び出し元は何ができるべきか。

## 最初のスライス

最初に作る価値のある最小の end-to-end の一歩は何か。

## 主要な判断

- インターフェースの判断
- データやスキーマの判断
- 統合方法の判断
- テスト方針の判断

## スコープ外

今回の作業で明示的に扱わないものは何か。
```

## ルール

- まずユーザーや呼び出し元の視点から書く。
- ファイルパスやコード片は、曖昧さを消すのに必要な場合だけ書く。
- 後から復元しづらい判断を残す。
- 実装中にも読み返せる程度の短さを保つ。
