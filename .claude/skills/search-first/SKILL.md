# 実装前の調査

必要な振る舞いと制約から、既存機能の再利用、依存の採用、薄い拡張、独自実装のどれを選ぶか決める。小さな既知の修正で外部調査を広げる必要はない。

## 進め方

1. 対象の入口・テスト・依存一覧を調べ、リポジトリ内で解決できるか確認する。
2. 不足があれば、利用可能な公式ドキュメント・パッケージ情報・上流コードで候補を調べる。利用していない検索先を調査済みと扱わない。
3. 必要な機能、既存スタックとの互換性、保守状況、ライセンス、追加依存、運用・セキュリティ上の負担を比較する。バージョンやAPIの判断は現行の一次資料で裏づける。
4. 候補を採用するか、既存機能を拡張するか、独自実装にするかを理由とともに決める。小さな用途のための大きな依存追加を避ける。

調査は依存のインストールや外部設定の変更を意味しない。実装を依頼されている場合は、その範囲内で決定を実装に反映し、必要な検証まで続ける。結果を変える未確定の業務判断だけ確認する。

## 結果

- 必要な振る舞いと既存の再利用先
- 比較した候補と採用理由、参照URL・対象バージョン
- 未確認事項と、その影響を確かめる最小の検証

単純な判断なら会話で短く残し、継続開発に必要な判断だけ既存のIssueや設計文書へ記録する。特定のMCP、研究用エージェント、モデル分業は前提にしない。
