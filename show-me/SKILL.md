# Show Me

いま話している対象を、理解に必要な最小の図で説明する。会話・実際のコード・確認済みデータを使い、説明と図を隣接させる。

## 表現を選ぶ

| 説明する関係 | 使う表現 |
|---|---|
| アルゴリズム・分岐 | 疑似コード |
| 呼出順・コンポーネントの責任 | 浅い呼出ツリー、コンポーネントツリー |
| ファイルの責任分担 | ファイルツリー |
| コンポーネント間の通信・状態遷移 | Mermaid |
| 既存構造からの変更点 | 小さなdiff |
| UI、比較、操作すると理解しやすい概念 | 単独で開けるHTML 1ファイル |

複数の表現を使う時も、同じ情報を繰り返さない。単一の事実や一手順で済む説明は短い文章にする。

## 作り方

1. ユーザーが理解・判断したい点を会話から特定する。
2. 必要なファイル・状態・入出力を確認する。未確認は未確認と表示する。
3. 判断に関係する境界と順序だけ残して図にする。
4. Mermaidやツリーで足りる時はそのまま応答する。
5. HTMLが必要ならプロジェクトの成果物用フォルダへ `show-me-<topic>.html` を作る。既存の配色や用語に合わせ、モバイルでも読めるレイアウトにする。
6. 利用できるプレビュー機能で開く。機能がなければファイルリンクを渡す。

HTMLには外部キー・秘密情報・未承認の外部送信を含めない。説明用画面の作成を、実アプリの実装・動作確認済みと取り違えない。

## 完了条件

- 対象の関係や違いが図だけでも追える
- 仮定と確認済みの値を区別している
- HTMLを作った場合は存在と構文・表示を利用可能な方法で確認し、表示未確認なら明示する

導入元と移植方針はリポジトリルートの `docs/skill-sources.md` を参照する。
