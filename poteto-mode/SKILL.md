# pstack開発モード

依頼に合うplaybookを選び、調査・設計・担当分離・実装・レビュー・実行検証を進める。必要なスキルと工程を主担当が選び、成果と証拠を確認して完了を判断する。

1. [実行対応](references/runtime.md) を読む。このセッションで読んでいれば再読不要。対象リポジトリのAGENTS.mdと、存在する場合だけルートの `.pstack-models.md` を確認する。
2. [上流のモード定義](UPSTREAM-SKILL.md) を読み、依頼に合うplaybookを選ぶ。大きな移行はfigure-it-out、継続した複数PRの運用はorchestrateの条件を確認する。
3. 選んだ `playbooks/<name>.md` だけを読み、工程をタスクリストへ写す。適用しない工程も理由を残す。原文のツール・モデル・プラグイン前提は実行対応へ読み替える。
4. 必要になったスキルの日本語入口を読み、参照と原則は該当するものだけ読む。上位指示が許可する環境で調査・設計・実装・レビューを分担する。
5. 受入条件を実物で検証し、差分と担当の成果を主担当が確認する。Linearの状態と検証証拠を更新し、未検証を残して報告する。

相談やレビューのみの依頼では読み取りを守る。ユーザーの停止・確認条件を引き継ぐ。独立レビューや複数モデル比較を実施できない場合は、その限界を報告する。

採用範囲と更新はリポジトリルートの `docs/pstack-adoption.md`。 / [上流記録](UPSTREAM.md)
