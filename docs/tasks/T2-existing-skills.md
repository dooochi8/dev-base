# T2: 既存6スキルの品質パス指示

対象: `dev-base` / `grill-me` / `write-a-prd` / `prd-to-issues` / `tdd` / `improve-codebase-architecture` のトップレベル `SKILL.md`。
`.claude/skills/` は触らない（sync で生成するため）。`references/` の内容変更も今回はしない。

## 目的

内容の大幅な書き換えではなく、(1) 構造の統一、(2) 実行者（軽量モデル）向けガードレールの前出し、(3) 新設スキルへの導線追加。既存の文章・語彙・思想は最大限保持する。

## 作業内容

### 1. ガードレールの前出し

各スキルで「やってはいけないこと」に相当する節（dev-base の「ガードレール」、tdd の「アンチパターン」など）を、frontmatter 直後の導入文のすぐ後に移動する。既存に無いスキルには追加しない（無理にひねり出さない）。

### 2. 実行者向けガードレールの追加（dev-base と tdd のみ）

`dev-base` と `tdd` のガードレール節に、軽量モデルが暴走しやすいパターンの禁止を追記する:

- 指示書や依頼に書かれていないリファクタ・依存追加・抽象化をしない
- 検証（テスト・型・lint の実行）をせずに完了を報告しない。完了前に `verify` の姿勢で確認する
- テストが落ちたとき、テスト自体を弱めて通さない

### 3. 新設スキルへの導線

- `dev-base` のリファレンスマップの後に「関連スキル」節を追加: orient（未知のリポ把握）/ debug(バグの原因特定) / verify（完了前の検証）/ review-diff（差分レビュー）への一行ずつの案内。
- `prd-to-issues` の完了条件の後に一行: 「issue を実行者へ渡すときは `plan-handoff` で実行指示書にする」。

### 4. description の見直し

各 frontmatter の description を確認し、「いつ使うか」が先頭付近で分かる形になっているか確認する。すでに十分なら変更しない。

## 受け入れ条件

- [ ] 6スキルすべてでガードレール相当の節が冒頭付近にある（元から無いものは除く）
- [ ] dev-base と tdd に実行者向けガードレール3点が入っている
- [ ] dev-base に関連スキル節、prd-to-issues に plan-handoff への導線がある
- [ ] 既存の本文内容が不必要に書き換えられていない（diff が構造移動と追記中心）
