## 1. docs/workflows.md の作成

スキルの連鎖パターンを、規模別に3本示す。各パターンは「どの場面で・どのスキルを・どの順で・何を受け渡すか」を書く。

- **小さな修正**: dev-base → verify。必要なら review-diff。
- **バグ修正**: debug →（再現テスト固定は tdd）→ verify。
- **中規模以上の機能開発（モデル分業）**:
  1. 計画側（高性能モデル）: orient（未知のリポなら）→ grill-me → write-a-prd → prd-to-issues → plan-handoff で issue ごとの実行指示書を作る
  2. 実行側（軽量モデル）: 指示書を受けて dev-base / tdd で実装 → verify で検証 → 報告
  3. 計画側: review-diff で差分レビュー → 必要なら修正指示を再度 plan-handoff で渡す

各ステップで「次のステップへの成果物」（PRD、issue 群、実行指示書、検証レポート、レビュー指摘）を明示する。
