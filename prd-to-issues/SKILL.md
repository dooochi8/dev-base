# PRD To Issues

PRD を、独立して進めやすい実装 issue 群に分解する。

## 進め方

1. 対象の PRD を読む。
2. 必要ならコードベースを探索し、現状との差分を把握する。
3. PRD を薄い縦切りへ分解する。
4. 各スライスの依存関係と完了条件を整理する。
5. ユーザーに粒度と依存関係を確認する。
6. 承認後、issue 形式でまとめる。

## 原則

- 横切りではなく縦切りで分解する。
- 各 issue は、それ単体で検証やデモができる粒度を目指す。
- 太い issue を少数作るより、細い issue を複数作る。
- ブロッカーを曖昧にしない。
- PRD の内容を丸写しせず、その issue で作る end-to-end の価値を書く。

## 各 issue に含めるもの

```md
## 親PRD

#<prd-id>

## 作るもの

この縦切りで実現する end-to-end の振る舞い。

## 受け入れ条件

- [ ] 条件1
- [ ] 条件2
- [ ] 条件3

## Blocked by

- #<issue-id>

依存がなければ "なし"

## 対応するユーザーストーリー

- User story 3
- User story 7
```

## 確認観点

- 粒度は粗すぎないか
- 依存関係は正しいか
- 分割より統合すべき issue はないか
- 最初に着手すべき tracer bullet が明確か

## 完了条件

- 全 issue が薄い縦切りになっている
- 依存関係が明示されている
- 各 issue に受け入れ条件がある
- PRD のどのユーザーストーリーに対応するか追える

issue を実行者へ渡すときは `plan-handoff` で実行指示書にする。
