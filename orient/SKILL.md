# Orient

未知のリポジトリの構造を最短で把握し、以降の作業に使えるマップを作る。
詳細を読み尽くすことが目的ではなく、「どこに何があるか」を素早く掴むことが目的。

## 基本姿勢

- 全部読まない。入口と主要経路一本を優先する。
- 把握に時間を使いすぎない。手がかりを積み重ねてマップを埋めていく。
- 推測で書いた項目は「推測」と明示する。事実と仮説を混ぜない。
- マップ作成段階でコードを変更しない。

## ガードレール

- 全ファイルを読んでから判断しようとしない。代表的な経路一本で十分。
- 分からない部分をマップから隠さない。「まだ分かっていないこと」として明記する。
- orient の出力を理由にコード変更を始めない。orient 完了後は別スキルで作業する。

## 進め方

1. README・設定ファイル（`package.json`、`pyproject.toml`、`go.mod` 等）を読んで技術スタックとプロジェクトの目的を掴む。
2. エントリポイント（`main`、`index`、`app` 等）を特定する。
3. 代表的な機能を一つ選び、エントリポイントから末端まで経路を一本トレースする。
4. テストの配置場所と実行コマンドを確認する（`package.json` の `scripts`、Makefile、CI 設定など）。
5. 規約を拾う（lint/format 設定、ディレクトリ構成の慣習、コミットルール等）。
6. 以下のマップフォーマットにまとめる。

## 出力フォーマット（マップ）

```md
## 技術スタック
言語、主要フレームワーク、ビルドツール

## ディレクトリ構成の要点
主要なディレクトリとその役割

## エントリポイント
アプリ・サービスの起動点となるファイルまたはコマンド

## 代表的な処理経路
トレースした機能名: 入口 → 中間層 → 出口の概略

## テスト
テストの場所と実行コマンド

## 規約
lint/format ツール、ディレクトリ慣習、その他のルール

## まだ分かっていないこと
探索できていない部分や、推測のまま残っている項目
```

## 完了条件

- 技術スタックとエントリポイントが特定されている
- 主要な処理経路が一本トレースされている
- テストの実行方法が確認されている
- 推測と事実が区別されている
- 「まだ分かっていないこと」が明示されている
